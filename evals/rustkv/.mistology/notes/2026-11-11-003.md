## 문제 상황
백그라운드 컴팩션과 포그라운드 플러시가 서로 반대 순서로 뮤텍스를 잡아 교착 발생

## v1 (오답) 2026-11-11
- 한 것: run_compaction에서 manifest 락을 먼저 잡은 채 활성 테이블 락 획득을 대기
- 틀린 증거: CompactionDeadlockError: lock order manifest -> memtable inverted
- 왜 틀렸나: 처음부터 틀림: 플러시 스레드는 활성 테이블 락을 쥔 채 manifest 갱신을 요청해 순환 대기가 형성됨

## v2 (오답, 한때 정답) 2026-11-11
- 한 것: try_lock 재시도 루프와 짧은 백오프로 교착을 우회
- 확인 근거: 단일 스레드 컴팩션 단위 테스트 통과
- 다음에는: 경합 시 try_lock 백오프로 교착 방지
- 틀린 증거: CompactionStarvationError: background compaction starved under write burst
- 왜 틀렸나: 바뀌어서 틀려짐: 쓰기 폭주 시 백그라운드 작업이 계속 락을 양보하며 세그먼트 파일이 무한 누적됨

## v3 (현재 정답) 2026-11-11
- 한 것: 전역 락 순서를 활성 테이블 스냅샷 복제 후 manifest 단독 잠금으로 일원화해 두 락을 동시에 쥐지 않도록 재설계
- 확인 근거: cargo test -p rustkv-engine concurrent_compaction_stress 통과
- 다음에는: run_compaction 수정 시 절대 두 뮤텍스를 중첩 보유하지 말고 불변 스냅샷으로 분리한다
