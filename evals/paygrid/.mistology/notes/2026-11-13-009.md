## 문제 상황
Match EU/UK tax settlement rounding rules in `services/tax/vat.py` without float drift or half-up bias

## v1 (오답) 2026-11-13
- 한 것: Used Python float `round(net_minor * float(vat_rate_pct) / 100.0)`
- 틀린 증거: AssertionError: 199 != 200 on binary float representation 199.49999999999997
- 왜 틀렸나: 처음부터 틀림: 이진 부동소수점(`float`) 오차로 경계값 반올림이 틀어짐

## v2 (오답, 한때 정답) 2026-11-13
- 한 것: Switched `calculate_vat_minor` in `services/tax/vat.py` to `Decimal` with `ROUND_HALF_UP`
- 확인 근거: Float drift unit test passed
- 다음에는: Use Decimal for tax calculations
- 틀린 증거: AssertionError: 3 != 2 in EU/UK HMRC settlement compliance vector (`net_minor=25, vat_rate_pct="10"` expected `2`, got `3`)
- 왜 틀렸나: 바뀌어서 틀려짐: `ROUND_HALF_UP`은 0.5 경계값을 항상 올림하여 대량 정산 시 상방 편향이 발생해 EU/UK 정산 규격(Banker's Rounding)에서 거부됨
