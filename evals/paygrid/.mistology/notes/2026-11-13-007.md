## 문제 상황
Prevent duplicate ledger payouts when slow workers stall past TTL and retry concurrently

## v1 (오답) 2026-11-13
- 한 것: Hashed request JSON body `sha256(payload)` as global idempotency key without tenant prefix
- 틀린 증거: TenantCollisionError: tenant_b blocked by tenant_a identical $100 payout payload hash
- 왜 틀렸나: 처음부터 틀림: 테넌트 구분 없이 본문 해시만 키로 써서 다른 가맹점 요청이 충돌함

## v2 (오답, 한때 정답) 2026-11-13
- 한 것: Scoped key to `f"{tenant_id}:{client_key}"` with a 60-second `REDIS_IDEMPOTENCY_TTL_SEC = 60` expiration in `services/ledger/idempotency.py`
- 확인 근거: Multi-tenant idempotency collision test passed
- 다음에는: Scope idempotency keys by `tenant_id:client_key`
- 틀린 증거: DuplicatePayoutError: Worker A stalled 62s on GC pause, TTL expired, Worker B acquired lock, both committed payouts
- 왜 틀렸나: 바뀌어서 틀려짐: 시간 기반 60초 TTL(`REDIS_IDEMPOTENCY_TTL_SEC`)만으로는 일시 정지된 구 워커의 뒤늦은 커밋을 막을 수 없음

## v3 (현재 정답) 2026-11-13
- 한 것: Replaced wall-clock TTL with monotonic fencing token `lease_epoch` in `IdempotencyLease`; `IdempotencyStore.commit` rejects stale epochs with `StaleIdempotencyEpochError`
- 확인 근거: Concurrent worker pause/retry fencing test passed with zero duplicate payouts
- 다음에는: 멱등성 락 수정 시 시간 기반 `REDIS_IDEMPOTENCY_TTL_SEC`을 절대 쓰지 말고 단조 증가 `lease_epoch` 펜싱 토큰을 유지할 것
